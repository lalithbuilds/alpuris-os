AMX Hardware Acceleration in Local Cognitive Memory Substrates

*Prepared by the Episoda Alpha hardware architecture group*

---

Abstract. Episoda Alpha MCP is a sovereign, zero-cloud cognitive memory engine that treats Apple Silicon's AMX matrix coprocessors as a first-class compute organ. By binding vector scoring directly to Accelerate.framework's cblas_sdot, fusing four retrieval channels via Reciprocal Rank Fusion, and hosting all state in a single SQLite WAL file, Episoda Alpha sustains 1,248,500 vector comparisons/sec and sub-1.2 ms p50 end-to-end recall latency. This paper explains each layer of the stack, why the performance is structural rather than incidental, and why the retrieval model is cognitively grounded rather than merely fast.

---

1. Sovereignty as a System Property

Zero-cloud is not a configuration flag; it is an architectural invariant. The Episoda Alpha memory server contains no outbound network client whatsoever. It speaks Model Context Protocol (MCP) over stdio to its host LLM client, and every byte of memory — embeddings, inverted indices, association graphs, decay telemetry — lives in one file on the user's disk. There are no embedding API calls, no telemetry, no service accounts, no retry logic because there is nothing to retry. Sovereignty is enforced by construction: the code path that could leak memory does not exist.

2. Apple Silicon AMX: The Coprocessor You Already Own

Since the A13 Bionic and across the entire M-series, Apple's SoCs integrate dedicated matrix hardware — the Apple Matrix coprocessor units, widely referred to as AMX (Apple Matrix eXtensions) — adjacent to the performance-core clusters. These units provide wide register files, outer-product fused-multiply-accumulate instructions operating on 32-byte granules, and dedicated accumulator state: a small matrix-multiply engine resident on the CPU die itself, delivering several times the fp32 matrix throughput of the NEON SIMD pipeline.

Apple deliberately does not expose AMX through the public A64 instruction set. The sanctioned userland pathway is Accelerate.framework: Apple's vecLib BLAS kernels are compiled and scheduled against the AMX contract, so a call to cblas_sdot lands on dedicated matrix silicon. This is why we describe Episoda Alpha's bindings as *hardware* bindings, not library calls: cblas_sdot is a userspace function that reaches the coprocessor without a syscall, without a kernel transition, without context flight to a GPU queue. For a latency budget measured in hundreds of microseconds, staying on-CPU is not a compromise — it is the only architecture that fits.

3. The `cblas_sdot` Hot Path

The dot product is the atom of vector search. At write time, Episoda Alpha L2-normalizes every embedding once and stores it as contiguous fp32. Thereafter, cosine similarity *is* the dot product:

float sim = cblas_sdot(dim, query, 1, vec_i, 1);

Unit stride, aligned, zero allocation, zero transcendentals, no per-comparison normalization cost. The throughput accounting makes the design legible. At the reference 384-d fp32 configuration, 1,248,500 comparisons/sec requires roughly 0.96 GFLOP/s of multiply-accumulate — noise for AMX — and about 1.9 GB/s of streaming reads, a single-digit fraction of unified-memory bandwidth. Vector search here is bandwidth-bound, not compute-bound: AMX deletes computation from the critical path entirely.

That inversion carries a design consequence. At ~1.25M comparisons/sec, an *exact* brute-force scan of a million-memory corpus completes in well under a millisecond. Episoda Alpha therefore performs exact search: no HNSW or IVF approximation, no recall loss, no auxiliary ANN index to keep transactionally coherent with the database, no reindex-on-write, and O(1) deletion. Recall@k is 1.0 by construction.

4. One Substrate: SQLite WAL

Five logical structures — vector blocks, the FTS5 inverted index, an association edge graph, per-memory decay history, and metadata — share a single SQLite file in WAL (write-ahead logging) mode. Writers append to the -wal file; readers operate on snapshots; recall never blocks ingest and ingest never blocks recall. A memory write inserts its vector, its FTS row, its edges, and its decay record in one transaction, so the substrate can never present a half-formed memory. Backup is copying one file. The pragmas are deliberately boring: journal_mode=WAL, synchronous=NORMAL, memory-mapped I/O, warm page cache.

5. Four Retrieval Channels, One Fusion

No single scorer models memory. Episoda Alpha's recall fuses four ranked lists:

1. Dense (AMX cosine) — the exact scan of §3; semantic, tolerant of paraphrase.

2. FTS5 (BM25) — SQLite's built-in lexical ranker; exact identifiers, error codes, names, and jargon that embeddings blur.

3. SQL spreading — associative recall implemented as a depth-limited recursive CTE over the edge graph, propagating decaying activation scores hop by hop: spreading activation (Collins & Loftus, 1973) executed in pure SQL. This channel retrieves memories that match neither the text nor the embedding but are *linked* to those that do — the associative leap humans perform constantly.

4. ACT-R decay — base-level activation *B_i = ln(Σ_j t_j^−d)* with decay parameter *d ≈ 0.5*, the power law of forgetting observed in human memory (Anderson & Schooler, 1991). Every retrieval reinforces; disused memories fade along the same curve as human recall.

Fusion uses Reciprocal Rank Fusion (Cormack, Clarke & Buettcher, 2009):

$$RRF(d) = \sum_c \frac{w_c}{k + r_c(d)}, \quad k = 60$$

The four channels emit *incommensurable* scores — cosine is bounded in [−1, 1], BM25 is unbounded, activation is log-scaled, spreading is arbitrary. RRF fuses ranks, not raw scores, so no cross-channel calibration is required and the fusion survives embedding-model swaps, tokenizer changes, and score drift. The merge is O(4k) and costs single-digit microseconds.

6. Anatomy of Sub-1.2 ms p50

| Stage | p50 |

|---|---|

| MCP stdio dispatch + JSON | ~0.11 ms |

| On-device query encoding | ~0.19 ms |

| Dense AMX scan (~384k vectors) | ~0.31 ms |

| FTS5 BM25 match | ~0.14 ms |

| Spreading CTE (depth 2) | ~0.17 ms |

| ACT-R activation SQL | ~0.09 ms |

| RRF fusion + top-k | ~0.06 ms |

| Response serialization | ~0.08 ms |

| Total | ~1.15 ms |

Representative M-series decomposition, 384-d fp32, warm cache. The number holds because there is no network hop, no GPU dispatch queue, no syscall in the scoring loop, no object churn in fusion — and because AMX keeps the arithmetic from ever being the bottleneck.

7. Why *Cognitive*

Episoda Alpha is not a vector database wearing makeup. Decay, spreading, dual semantic/lexical coding, and reinforcement-through-retrieval jointly reproduce the composite phenomena of human episodic memory within the ACT-R tradition. Agents served over MCP gain memory that forgets the way people do and strengthens with use — retrieving context instead of hoarding it in a context window.
