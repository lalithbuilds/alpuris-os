Abstract

PIANO (Parallel Input Aggregation, Nested Output) is the dual-speed cognition kernel of ALPURIS OS, an open-source living agent metropolis sustaining 100 autonomous AI citizens across 23 dynamic sectors with real-time stock markets and zero-asset procedural audio. PIANO partitions cognition into two asynchronous clock domains: a deterministic System-1 reactive tick loop executing perception, locomotion, drive satisfaction, and market clearing at 10 Hz without model calls, and a triggered System-2 reflection layer performing deliberate LLM reasoning over aggregated memory to revise goals, monologue, and dialogue intent. A salience-weighted tiered memory substrate with LLM compaction bounds context growth across days of city life, while ECS spatial neighborhood hashing reduces co-presence, collision, and audio-voice queries from O(n²) to O(k). The result is a fully client-side, replayable metropolis in which expensive deliberation is spent only where it changes the story.

1. Introduction

Generative-agent simulations fail at metropolitan scale for a simple reason: if every micro-decision is a model call, a city of 100 citizens becomes either unaffordable or unresponsive. ALPURIS OS [1] was architected on the opposite premise — a believable city is mostly cheap computation, punctuated by rare, expensive thought. PIANO operationalizes Kahneman's dual-process theory [3] as an engineering contract: System 1 is fast, automatic, and deterministic; System 2 is slow, deliberate, and invoked only when the reactive layer signals that cheap cognition is insufficient. The design descends from the PIANO multi-agent framework [4] but restores Kahneman's original semantics: in ALPURIS, System 1 is the hot tick loop and System 2 the cold reflective path. This paper specifies both clock domains, the memory compaction that feeds them, and the ECS spatial hashing that makes a 100-citizen metropolis tractable in a browser with no backend.

2. Architecture Overview

PIANO comprises three cooperating layers over a shared ECS store:

1. System-1 tick loop — fixed-step deterministic simulation (10 Hz) owning motion, drives, schedules, and market clearing.

2. System-2 reflection engine — asynchronous, triggered LLM inference producing nested structured output.

3. Memory substrate — working, episodic, semantic, and identity tiers with compaction and hybrid retrieval.

The layers never block each other. Reflection runs off the critical path; results commit through a staging buffer at the next tick boundary, so the simulation advances at constant frame cost regardless of inference latency.

3. System-1: The Reactive Tick Loop

System 1 executes a fixed timestep of dt = 100 ms, decoupled from rendering via an accumulator pattern: the render loop drains accumulated wall-clock time into whole ticks, carrying surplus forward. Determinism is absolute — identical seeds replay identical cities.

Each tick runs four phases for every citizen archetype:

1. PERCEIVE. Pull the co-present neighborhood from the spatial hash (§6) plus sector events (price moves, openings, closures) into the working-memory ring buffer.

2. DECIDE. Score candidate actions by utility U(a) = Σ wᵢ·dᵢ(a) over drives — hunger, rest, wealth, social, purpose — with hysteresis to suppress oscillation. No LLM is consulted; weights are set at last reflection.

3. ACT. Execute steering along the sector road graph, queue dialogue initiation, place or cancel market orders.

4. INTEGRATE. Update kinematics, drives, and emotional vector; append salient events to episodic memory. Per-sector limit order books clear at the tick boundary, driving the real-time stock market.

Archetype-packed component arrays keep the loop data-oriented; the full 100-citizen tick budgets under 8 ms on commodity hardware, preserving headroom for 60 fps rendering, synthesis, and UI.

4. System-2: Reflection Triggers

Reflection is not a loop but an interrupt. Five trigger classes escalate a citizen from reactive to deliberative cognition:

| Trigger | Condition | Typical rate |

|---|---|---|

| Temporal | Baseline cadence, jittered ±20% | ~every 300 ticks (30 s) |

| Novelty | Unseen entity/sector/event class enters perception | bursty |

| Drive imbalance | Any drive beyond θ for T consecutive ticks | rare |

| Social | Co-present agent initiates dialogue | bursty |

| Market shock | Sector volatility index crosses σ | event-driven |

On trigger, PIANO assembles a single parallel aggregated input: the working-memory ring buffer, top-k retrieved episodic records (§5), a sector digest, open goals, and pending social signals. The model emits a nested output — a structured object containing inner monologue, goal deltas, dialogue intents, memory write directives, and optional sector actions. Strict budgets (≈2,000 input tokens, ≈400 output) and a per-citizen daily reflection allowance keep 100 deliberating citizens economically viable; jittered dispatch prevents a thundering herd of simultaneous calls.

The decisive engineering rule: reflection is asynchronous and non-authoritative until commit. Outputs land in a staging buffer and apply atomically at the next tick boundary, so inference latency can never stall the metropolis, and every deliberation is replayable as a logged event.

5. Memory Compaction

Unbounded memory is the silent killer of long-running agent cities. PIANO uses four tiers:

  • **Working memory** — fixed 512-slot ring buffer of raw per-tick perceptions.
  • **Episodic memory** — timestamped events scored by salience S = α·novelty + β·|emotional valence| + γ·social weight.
  • **Semantic memory** — distilled facts, preferences, relationships.
  • **Identity** — a stable core sheet plus milestone summaries regenerated on career or relationship shifts.

    • Compaction is salience-weighted and event-driven. When the episodic tier exceeds its entry or token budget, a summarization pass clusters low-salience, thematically adjacent events and folds each cluster into a semantic delta, deleting the originals. Salience decays as S(t) = S₀·2^(−t/τ), with half-life τ stretched for emotionally charged events — a market crash or falling-out outlives a routine commute. FIFO eviction is the last resort; no event is compacted twice. Retrieval at reflection is hybrid — lexical scoring plus embedding cosine — returning top-k = 8 records to the prompt. In practice, a 24-hour city day accumulates hundreds of episodic entries that compact into tens of semantic facts, holding every reflection prompt inside budget indefinitely. All compaction operations are logged, so memory state is exactly reconstructible on replay.

    6. ECS Spatial Neighborhood Hashing

    ALPURIS OS is a pure entity-component-system store: citizens, buildings, market markers, and audio emitters are IDs; behavior lives in systems iterating archetype-packed component arrays. Spatial locality — the basis of perception, dialogue, collision, and audio — is served by a uniform-grid hash over the world plane.

    Entities are binned into cells of size c = 2r, where r is the perception radius (~12 m), keyed by prime-mixed hashing:

    h(cx, cy) = (cx · 73856093 ⊕ cy · 19349663) mod M

    with M the next power of two ≥ 4n. Because c ≥ 2r, any neighbor query reduces to a 3×3 cell scan, so per-citizen perception costs O(k) neighbors instead of O(n²) pair tests — the difference between 10,000 and a few hundred distance checks per tick. Only entities that moved since the last tick are re-hashed (dirty-flag reinsertion).

    The same structure powers three subsystems: co-presence gating for dialogue initiation; Web Audio voice culling, where only emitters within audible radius receive procedural synthesis graphs, honoring a hard 16-voice budget with zero audio assets on disk; and event broadcast, which lets sector events reach nearby citizens first, so news propagates socially rather than globally. Spatial queries amortize below 1.5 ms per tick at full population.

    7. Sovereign Implementation

    Every layer above runs client-side. There is no backend and no asset pipeline: audio is procedurally synthesized through Web Audio, stock markets are in-browser matching engines, and PIANO's determinism boundary makes the entire metropolis replayable from a seed plus a log. This is the sovereignty thesis of ALPURIS OS [1] — a city you can run, audit, and own. Episoda Alpha MCP extends the same episodic-memory discipline to developer tooling.

    8. Conclusion

    PIANO demonstrates that believable agent metropolises do not require model calls per decision. By splitting cognition into a deterministic 10 Hz System-1 loop and a triggered, staged-commit System-2 reflection engine, bounding memory growth through salience-weighted compaction, and indexing the world with ECS spatial hashing, ALPURIS OS sustains 100 autonomous citizens, 23 live sectors, and real-time markets entirely in the browser. Dual-speed cognition is not an optimization; it is the load-bearing architecture of sovereign agent cities.
